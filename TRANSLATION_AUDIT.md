## Migration contract

From the current project:

```sh
mpress translate migrate-state --from ../original-project --lang fr --json
mpress translate migrate-state --from ../original-project --lang fr --write
```

The original project must contain its source, target, configuration, and sidecars
from the same snapshot. A mechanically renamed sidecar is not historical proof.
The default run is read-only. `--write` changes sidecars only; repeat runs leave
completed migrations byte-identical. No provider is contacted.

Migration inserts tracking markers into prose while preserving the original
inline and component syntax, passes them through the actual converter, and
requires the projected document structure to match. Matching numeric IDs alone
is not accepted as evidence. Approvals and provenance carry forward only when
source/target evidence verifies the mapping. Code-only segments can use exact,
unique source-and-target content as an independent witness. The original segment records and
snapshot hashes remain in the sidecar as historical evidence.

Uncertainty produces `migration-review`. Provider updates and refinement of that
page stop until an explicit review. Inspect and correct the page, then use:

```sh
mpress translate review --lang fr --file path/to/page.md
```

Review validates protected structure before recording approval. The migration
report distinguishes pre-existing layout differences, changes after the original
snapshot, untracked/stale original state, missing targets, and unmapped content.
It does not manufacture approval for already-stale translations.

`translate audit` and `translate check` inspect content independently of sidecar
freshness. A clean content audit does not approve migration state. Existing audit
exceptions also remain tied to their recorded file hashes and segment IDs; they
must be revalidated against the new representation.

## Remaining limitations

- Custom component grammars and labels embedded inside inline HTML still need
  manual coverage review. This does not claim arbitrary component support.
- Audit keeps strict destination and structure checks. Equivalent authored URL
  aliases or extra stable-anchor HTML may require deliberate content alignment;
  no blanket exception bypass was added.
- Automatic adoption cannot establish freshness for human translations without
  historical state. Restoring the original triplet or reviewing the result is
  required.
- Launchers still reuse an installed M-Press without a site-defined minimum
  version contract. Schema 2 prevents older engines from reading new sidecars,
  but an immutable compatible release is still needed for deployment.
- Wails currently pins the published v1.0.17 artifact. A local tested binary is
  not a published compatibility release; production integration remains a
  separate release step.
